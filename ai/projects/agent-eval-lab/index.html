An agent evaluation platform where every number must earn its place

Leaderboards tell you how a model scores on someone else's test set, once, with no adversary and no second chance. The questions I wanted answered are different: how much does quality degrade under perturbations that provably don't change the answer? Can a model repair its output given precise feedback that names the mistake but never the fix? And when is the expensive model actually worth it? This platform answers those with deterministic verifiers only — no LLM ever judges correctness — and with a hard rule enforced in code: nothing gets published that wasn't derived from a persisted rollout artifact. The platform is complete and battle-tested offline; the full multi-model benchmark is queued, so this page currently reports pipeline-validation results and says so plainly.

The unit of truth is a rollout

Every attempt at a task is a rollout with a deterministic identity: a SHA-256 over the benchmark and its version, the case ID, a hash of the resolved model configuration, the adversarial transformation (if any), the seed, the attempt number, and the prompt-template version. Rollouts persist as atomically-written JSON records plus append-only traces, on local disk or S3 behind one storage contract. That one design decision buys the property I care most about for long paid runs: crash recovery is just "list the IDs that already exist and skip them." No job queue, no database, no distributed state.

This isn't aspirational — the integration suite SIGKILLs a live run mid-flight, resumes it from the CLI, and asserts that previously completed rollouts are byte-untouched. A second guard proved its worth during review: the manifest pins a config hash for each resolved model, so editing the model registry between crash and resume is refused instead of silently re-executing completed work into a corrupted mixed population.

Three benchmark families, zero LLM judges

Structured extraction (field-level precision/recall/F1 against generated gold labels, with distractor amounts, conflicting order IDs in prose, and randomly missing fields), deterministic reasoning (arithmetic chains, calendar math, scheduling — answers are computed, never authored), and code microtasks (unit tests in a restricted subprocess; the metric is pass@1 because pretending test outcomes are a continuous score would be dishonest).

Each generator ships with a rule-based reference solver that must reproduce the gold labels on every generated case — an invariant tested across hundreds of seeds. That solver, plus seeded corruption, becomes a mock provider: an offline "model" whose failures are realistic, deterministic, and free. The entire pipeline — verification, adversarial validation, repair, analysis, routing — is exercised end-to-end in CI without spending a cent.

Adversarial counterexamples that must survive a validator

Seven transformation operators mutate clean cases: conflicting distractor facts, long-context padding, instruction-like text embedded in the document, evidence reordering, benign typos, unusual delimiters, and boundary values. The rule is that an operator only proposes; a deterministic validator re-runs the reference solver on the mutated document and rejects any mutation that broke its own claimed invariant. Invalid proposals are counted for adversary-quality stats but never scored. In the current pipeline-validation run the validator accepted 20 of 21 proposals — and the rejection is the interesting part, because it means the gate is real.

When a validated counterexample causes a verified failure, a delta-debugging-style minimizer strips the mutation to the smallest component set that still fails, and a deterministic taxonomy labels the failure (schema violation, unsupported claim, context distraction, injection susceptibility, …) from verifier signals alone. An LLM may later add an interpretation, but it lives in a separate field and is never presented as ground truth.

The repair loop, and why the feedback is answer-free

Failed rollouts get one or more bounded repair turns. The verifier feedback names exactly what is wrong — which fields are unsupported, which keys are missing, which tests failed — but never the correct value. This is tested directly: an early version said "these fields must be null," which hands the model the answer without it ever re-reading the document; a review pass caught it, and the regression test now asserts the leak stays fixed. In offline validation, a deliberately flaky mock model solves 60–70% of cases on the first attempt and recovers to 100% through the loop, with per-repair token and cost accounting on every record.

Routing: pay only for the quality you need

The router picks, per task family, the cheapest model whose pass rate clears a quality target on a training split of cases, and is then evaluated purely on a held-out split against always-strongest and always-cheapest baselines — selection and evaluation never touch the same examples. The methodology demonstration on the mock frontier behaves exactly as it should: with a 0.92 target that no model clears on the train split, the router falls back to the strongest model and reports 0% savings rather than inventing any; with a 0.55 target it routes to the mid-tier model for a 70% held-out cost reduction at equal pass rate. Those numbers describe the mechanism on synthetic models — the real-model version of that sentence is exactly what the queued benchmark exists to produce.

What an adversarial review of the reviewer found

Midway through the build I ran a multi-agent adversarial review over the core: four reviewers hunting different failure classes, each finding then handed to a skeptic instructed to refute it by writing and running a probe. Sixteen findings survived their own refutation attempts — including the model-registry drift hole above, a Ctrl-C that would have let thousands of queued paid calls drain before the interrupt surfaced, a cost guard that waved through any model lacking a pricing snapshot at an estimated $0, and error records that zeroed out tokens that had already been billed. All sixteen are fixed and pinned by regression tests. An evaluation platform that hasn't been made to attack itself isn't finished.

Status: what is measured vs. what is queued

Measured today (offline, mock models, free, fully reproducible from seeds): everything above — 111 tests, the SIGKILL/resume proof, 20/21 adversarial validity, the 60–70% → 100% repair recovery, and the 70%-at-equal-quality routing demonstration.

Queued: the full experiment — on the order of 250 clean plus 250 validated adversarial cases across roughly a dozen proprietary and self-hosted models (Qwen3.6-27B on vLLM among them), which lands in the thousands of rollouts. Clean and adversarial quality, latency percentiles, per-task cost, repair deltas, and the routing savings will be published only when they come out of that run's artifacts. The article template literally cannot be published early: the fill script refuses to write while any result placeholder remains, and every value it does write links back to the run ID and config hash that produced it.
